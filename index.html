RegionAlign

Rearranging where an AI model's weights are stored — without changing a single value — to make one physical glitch far more damaging.

A malicious model provider never touches the numbers inside the model, so it behaves identically and passes every quality check. All they change is the layout: which weights sit in which patch of memory. That quiet rearrangement herds the model's most fragile weights into one small region — so a single localized hardware fault there breaks the model, where the same fault on the original layout barely registers.

The setup

Two known threats that nobody had connected

AI models are often built and shipped by someone else. Separately, hardware attacks can flip individual bits in memory. On their own, each is manageable. RegionAlign shows what happens when one sets up the other.

Threat A · supply chain

A tampered model

You download a model from a third party. If it still answers correctly, it looks trustworthy — but a provider can hide changes that only show up later.

Threat B · hardware

A physical glitch

With physical access, an attacker can zap a chip (e.g. with an electromagnetic pulse) and flip bits of the stored weights in one small area of memory.

RegionAlign makes Threat A quietly load the gun for Threat B.

The key idea

It's about where things are stored, not what they are

A model has millions of weights. A few of them are fragile: flip a bit and the model's quality collapses. Normally those fragile weights are scattered all over memory, so one localized glitch only touches a handful.

RegionAlign reorders the weights — a shuffle that leaves the math exactly the same — so the fragile ones end up packed into one pre-chosen region. Nothing about the model's behavior changes. The trap is purely in the arrangement.

Think of a moving crate

Imagine packing a crate. The same items go in — nothing added, nothing removed, so it weighs the same and passes inspection. But you quietly move every breakable item into one corner. Now a single knock to that corner shatters far more than a knock would have before. RegionAlign does this with a model's fragile weights.

How it's done

Three steps, no retraining, no changed values

Find the fragile weights

A guided search measures which weights, if corrupted, hurt the model most — and how to flip their bits for the biggest effect within a fixed budget.

Herd them into the target region

Equivalent "channel permutations" (borrowed from model-compression tricks) reorder weights so the fragile ones land inside one aligned 4 KB region, while the model stays mathematically identical.

Pass every clean check

Each prepared layout must match the original's accuracy and perplexity before it counts. The tampering is invisible to anyone evaluating task performance.

Identical when clean. Not identical when hit.

Vision models fall off a cliff

For Qwen2.5-VL-3B, a single in-region bit flip under RegionAlign drops its score on both image-question tasks below 1 (out of ~60 and ~88 clean) — while the original and random layouts stay near their clean scores under the exact same fault.

Why it works: almost all selected flips hit the most-significant bit of a near-zero weight. RegionAlign moves weights whose rows allow large values into the region, so one flip swings them hard — a leverage the other layouts simply don't have in that region.

The honest limit

Hitting one region physically is hard — and that's exactly the point.

We confirmed on real hardware (an NVIDIA Jetson AGX Thor) that electromagnetic pulses genuinely corrupt stored weights, in both directions, as our model assumes. But across 2,500 attempts, none precisely landed on the pre-chosen target. So RegionAlign's power isn't a claim that physical aiming is easy. It's that once the attacker is constrained to a region, the layout they chose decides how much damage a fault there can do.

Why it matters

A clean-looking model can still be a trap

Checking quality isn't enough

A tampered model matches the original on every accuracy test. Resilience to physical faults has to be checked separately — behavior alone won't reveal it.

Two fields have to talk

Model supply-chain security and hardware fault-injection security were studied apart. This work shows how a layout choice links them.

Layout deserves attention

Where weights are stored is usually treated as a harmless detail. RegionAlign shows it can be a deliberate attack surface.
